Docs

How the Claudegotchi works, how to set it up and how to change it.

Overview

The Claudegotchi has two halves:

  • The gotchi: a Raspberry Pi Zero with an e-paper display, running its own small Buildroot image. A Python service receives events, works out a mood and draws it.
  • The client: a small Python script on your computer. Claude Code runs it as a hook on every event and as the status line. It sends metadata to the gotchi and never blocks Claude Code: sending happens in a detached background process.

The gotchi listens on port 8765. Over the USB cable it is at 192.168.77.1, on Wi-Fi at claudegotchi.local. A live preview of the display is at http://claudegotchi.local:8765/.

With several sessions (for example worktrees), the state that needs you most wins. The footer shows how many sessions are working (▶), waiting for you (?) or done (✓), plus bars for the 5-hour and 7-day budget. The header shows the level and the number of sessions.

Growing up

The critter earns experience from your work:

  • 10 XP per finished reply
  • 5 XP per completed task
  • 3 XP per new session
  • 1 XP per tool call

Levels get further apart as it grows: level 2 at 50 XP, level 3 at 150, level 4 at 300, and so on. Every day with at least one finished reply extends the streak; skip a day and it starts over. In the evening it shows what you did today, and when you leave it alone for two days it gets hungry.

The progress lives in life.json on the image's small writable data partition, so it survives reboots and updates. In the simulator it is in ~/.claudegotchi/.

The client

Install it from a copy of the repository. It works on macOS and Linux.

python3 client/install_mac.py                                  # automatic: USB cable, then Wi-Fi
python3 client/install_mac.py --url http://192.168.1.50:8765   # a fixed address
python3 client/install_mac.py --token my-secret                # with a token
python3 client/install_mac.py --uninstall                      # remove it again

The installer copies claudegotchi_client.py to ~/.claude/claudegotchi/ and adds the hooks and the status line to ~/.claude/settings.json. It backs up the old file as settings.json.claudegotchi-backup. Existing hooks stay, and an existing status line is still shown.

To check the connection, play the test sequence. It walks through the moods over about a minute and prints which address answered:

python3 ~/.claude/claudegotchi/claudegotchi_client.py test

Settings

Open http://claudegotchi.local:8765/settings, or http://192.168.77.1:8765/settings over USB. The page changes Wi-Fi, time zone, rotation, token and relay. It writes claudegotchi.toml on the boot partition, keeps the comments in it, and restarts the gotchi. Once a token is set, the page asks for it.

You can also edit the file directly: put the card into your computer and open claudegotchi.toml on the CLAUDEGOTCHI drive.

[device]
display = "waveshare_2in13_v4"
rotate = 0                    # 180 if the picture is upside down
timezone = "Europe/Berlin"

[server]
port = 8765
token = ""                    # only accept clients that send this token

[usb]
enabled = true                # network adapter on the USB data port
address = "192.168.77.1"

[wifi]
ssid = ""                     # empty: USB cable only
psk = ""
country = "DE"

[relay]
url = ""                      # ntfy topic for Claude Code in the cloud
auth = ""                     # access token for a protected ntfy server

Without Wi-Fi the gotchi takes the time from your computer. With Wi-Fi it uses NTP.

Security

By default anyone who can reach the gotchi on port 8765 can send it events. On your desk over USB that is just your computer. On a shared Wi-Fi, set a token: put it under [server] token on the gotchi and install the client with --token. The settings page and app updates then need the token too.

The image has no SSH. The root filesystem is read-only.

Claude in the cloud

Hooks run wherever Claude Code runs. A session in the cloud, for example in a Claude Project, runs in a container that cannot see your local network. For that case the gotchi can listen to a relay: an ntfy topic. Cloud hooks publish to the topic, and the gotchi keeps one outgoing connection to it, so it works behind any Wi-Fi, even a phone hotspot.

  1. Create a relay topic and a token on your computer:

    python3 client/install_mac.py --new-relay

    It prints a [server] token and a [relay] url. Put both into the gotchi's settings and give it Wi-Fi.

  2. Print a setup script for the cloud environment and paste it into the environment's setup script:

    python3 client/install_mac.py --cloud-setup > cloud-setup.sh

    The script carries the client inline and installs it so that it only publishes to the relay.

  3. Allow ntfy.sh in the cloud environment's network access settings. Without it, the hooks cannot reach the relay.

The topic name is the secret: anyone who knows it can read the events (metadata only) and could publish to it. The gotchi ignores relay messages without the right token. You can run your own ntfy server and point --relay at it; set [relay] auth if it needs an access token.

Updates

The Python app updates in place. Only kernel or system changes need a new image.

make update GOTCHI=http://claudegotchi.local:8765 TOKEN=your-token

This packs app/ into output/claudegotchi-app.tar.gz and sends it to the gotchi. You can also upload that file on the settings page; every GitHub release carries one.

The gotchi checks that the new version starts, keeps it in /data/app, and restarts. If it crashes three times in a row right after starting, it falls back to the version built into the image. "Back to the built-in version" on the settings page does the same by hand.

Simulator

Try everything without hardware. You need Python 3.9 or newer and Pillow.

python3 -m pip install pillow
make test
make sim                    # preview at http://localhost:8765/  (other port: make sim PORT=8766)
CLAUDEGOTCHI_URL=http://localhost:8765 python3 client/claudegotchi_client.py test
make mockups                # every mood in docs/mockups.png

The simulator keeps its own copy of the settings in ~/.claudegotchi/claudegotchi.toml, so the settings page does not change the template in the repository.

The image

The operating system is built with Buildroot from the os/ folder. There is one configuration per board:

make zero2w     # Raspberry Pi Zero 2 W (64-bit)
make zerow      # Raspberry Pi Zero W

On GitHub, the workflow image.yml builds both images for every v* tag and attaches them to the release, together with the app bundle.

  • Read-only root filesystem, /tmp and /run in RAM. Pulling the plug does not hurt the card.
  • A 16 MB writable data partition at /data for the critter's progress and app updates.
  • BusyBox init with a few scripts: read settings, USB gadget, Wi-Fi, then the service.
  • USB gadget as a CDC-ECM network adapter with a DHCP server for your computer.
  • avahi for claudegotchi.local, NTP on Wi-Fi.
  • No SSH, no Debian, no Wi-Fi hacking tools.

Privacy

Only metadata is sent: event name, session ID, project folder name, tool name, notification or error type and limit percentages. Prompts, code and replies never leave your computer. With a relay, that metadata passes through the ntfy server you chose.

Troubleshooting

The display stays blank

  • Check that the HAT sits flush on all 40 pins.
  • Check that it is the V4 revision of the 2.13" display.
  • Give it a moment: an e-paper refresh is slow and the first boot takes a little while.

The computer does not see the gotchi

  • The cable must be in the port labelled USB, not PWR.
  • Try another cable. Many micro-USB cables only charge and carry no data.
  • Open http://192.168.77.1:8765/ in a browser. If the preview loads, the connection works and the problem is in the client setup.

The critter does not react to Claude Code

  • Run the test sequence (see the client). It prints which addresses it tried.
  • If the gotchi has a token, the client needs the same one: reinstall with --token.
  • Start a new Claude Code session after installing; running sessions keep their old settings.

The picture is upside down

Set rotate = 180 on the settings page.
